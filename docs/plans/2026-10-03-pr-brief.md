# Development Plan — PR Brief (Overview-tab why + risk card, one grounded model call, PR-keyed cache)

## Source requirements
`specs/2026-10-03-pr-brief.md` (SPEC-2026-10-03-pr-brief) — covers **AC-1 … AC-24** (all, including the three P3s; user override 2026-10-03: AC-22 in scope). All five former clarification items are settled in the spec's "Resolved decisions": 12,000-token input budget / 3,000-token completion cap; `intent`/`blast`/`history` optional in `PrBrief` plus additive `summary` and `review_focus: [{ file, line, reason }]`; attached specs = the repo's discovered Project Context documents under per-doc/total caps; stale cache = serve + visible indicator, regenerate only on explicit refresh; concurrent POSTs tolerated, last successful write wins.

## Goal
A reviewer opening a PR cold reads one card on the Overview tab — short summary (what & why), Risk areas, Review focus ("read these first", clickable into the Files changed tab at that file/line) — generated by exactly one bounded model call over precomputed facts only, mechanically grounded so invented paths never render, cached per PR so revisits cost zero model calls, with staleness, missing-data, and failure states that never destroy the previous brief.
