# Development Plan — Eval Pipeline (regression evals for review agents)

## Source requirements
`specs/2026-10-10-eval-pipeline.md` (Status: approved, sign-off 2026-10-10) — covers **AC-1 … AC-41, all of them** (coverage map in Tasks; every task cites its ACs). The spec's single `[NEEDS CLARIFICATION]` — sweep grouping under the fixed `eval_runs` DDL — is resolved here:

**Decision: a stable sweep key embedded in the `eval_runs.actual_output` jsonb envelope.** `actual_output` stores `EvalActualOutput = { sweep_id, agent_id, agent_version, findings, pre_grounding_count, error }` (a fresh UUID per sweep trigger, written identically to every row). Justification: (a) AC-13 demands a *stable identifier* — timestamp proximity is not one (per-row `now()` defaults; interleaved concurrent sweeps) and cannot carry the AC-14 version link; (b) zero DDL change — `server/src/db/schema/eval.ts` already matches the applied `0000_init` DDL exactly (verified column-by-column) and the spec's data-shapes section explicitly reserves `actual_output` for "whatever sweep-grouping metadata the plan settles on"; (c) gold sets are single-digit, grouping runs in JS over rows already fetched — no jsonb SQL path/index needed. Rejected: shared-timestamp derivation (unstable identity, conflates `ran_at` semantics) and the new append-only migration column (sanctioned fallback, but unnecessary churn at this scale). **No migration is generated by this plan.**

## Goal
Users convert accepted/dismissed findings into fixed-input eval cases, run an agent's whole gold set with one deterministic scoring pass (recall / precision / citation accuracy, zero LLM calls in scoring), compare sweeps across agent versions (with system-prompt diff and one-click Promote of an old config), and see it all on a new Eval Dashboard — so a prompt change visibly moves the metrics.
